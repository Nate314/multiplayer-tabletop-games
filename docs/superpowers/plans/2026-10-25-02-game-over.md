# Game-Over Screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every game ends on the same summary screen (winner or Draw, game name, ID and length, final standings in the game's own terms, then History, See the table and Back to games), and the server reports each finished game once through `onGameFinished`.

**Architecture:** Each game may supply `finalStandings(state)`, built with one shared ranking helper, and `standingsOf` falls back to `winners`. The manager adds the standings to every game-over view and stamps `startedAt` and `finishedAt` in the one place every change passes through (`save` in `server/games.ts`), which is also where `onGameFinished` fires. The client shows `GameOverDialog` from `GameView`. The nine round games stop showing their last round summary and hand its rows to the game-over screen as `ClientGame.FinalRound`.

**Tech Stack:** TypeScript, React 19, node:test, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-25-spectators-social-and-new-games-design.md`, feature 2. Index plan: `docs/superpowers/plans/2026-10-25-spectators-social-and-new-games.md` (Shared contracts: Standings, Game end). Branch `game-over` from master, wave 1, PORT 3102, E2E_PORT_BASE 6130.

## Global Constraints

All of the index plan's Global Constraints, plus:

- Implement exactly the index contracts `Standing`, `GameDefinition.finalStandings`, `standingsOf` (`shared/standings.ts`), `GameResult` and `onGameFinished`. Two clarifications this plan pins: with no winners (a draw) every seat is at place 1; standings list `activePlayers` at the end (seats dismissed or left earlier are not ranked).
- Each `finalStandings` ranks by the same quantity the game's own end logic used to choose `winners`, so the seats at place 1 are exactly `winners`. It may only read what is public once the game is over.
- Spectators arrive in plan 1, in parallel. Do not build anything for them; leave `canRematch(state, viewer)` (below) as the single place the "no Rematch for spectators or table screens" rule lives. The Rematch button itself is plan 3's.
- New state fields are optional, so rooms saved before this change load.

## Review Focus

1. A game ends outside a move (resignation, agreed draw, a dismissal leaving one player, a clock timeout): the screen still shows and `onGameFinished` fires once (Task 2 tests `concede`, `dismissal`, `timeout`).
2. Undo after game over, then the game ends again: no second `onGameFinished`, and the screen opens again even if it was closed before (Task 2 test, Task 4 `closed` reset).
3. A room saved before this change, finished or mid-game, loads without firing `onGameFinished` and still shows standings (Task 2 test).
4. A game's `finalStandings` throws on an odd state: the view still builds, using the fallback (Task 1 test). Without this, one bad hook breaks every view of that game.
5. Long names or 8 to 10 players at 320 px: the standings list scrolls inside the dialog and the four buttons wrap without overflow (Task 4 browser check).

### Task 1: Standing type, ranking helper and fallback

**Files:**
- Create: `shared/standings.ts`, `shared/standings.test.ts`
- Modify: `shared/types.ts`, `shared/gameDefinition.ts`

**Interfaces:**
- Produces in `shared/types.ts`: `type Standing = { seat: Seat; place: number; score?: string }`; `type GameResult` exactly as the index contract; on `BaseGameState` the optional `startedAt?: number` (server ms of the first move), `finishedAt?: number` (when `isGameOver` first became true) and `gameNumber?: number` (the `n` of `archiveId`, missing means 1; plan 3 sets it); on `BasePublicState` `standings?: Standing[]` (present only when `isGameOver`).
- Produces in `shared/gameDefinition.ts`: `finalStandings?(state: S): Standing[]` with a one-line comment (called only once `isGameOver`).
- Produces in `shared/standings.ts`:
  - `rankStandings(state: Pick<BaseGameState, 'activePlayers' | 'winners'>, compare: (a: Seat, b: Seat) => number, score?: (seat: Seat) => string): Standing[]`: winners at place 1; everyone else dense-ranked below them by `compare` (negative means `a` ranks higher; equal shares a place); with no winners the ranking starts at 1. Rows sorted by place, then seat.
  - `standingsOf(definition: Pick<GameDefinition, 'finalStandings'>, state: BaseGameState): Standing[]`: the hook's rows, or `rankStandings(state, () => 0)` without one. A hook that throws is logged with `console.error` and the fallback is returned.
  - `pointsText(points: number): string` = `plural(points, 'point')` with `toLocaleString('en-US')` digits, the common score text.

  - `the fallback with no winners is a draw at place 1`: every row `place: 1`.
  - `rankStandings dense-ranks the rest and ties share a place`: Hearts-like scores `{1: 30, 2: 80, 3: 30, 4: 101}`, low wins, winners `[1, 3]`, score `pointsText`: places `1, 1, 2, 3` for seats `1, 3, 2, 4`; seat 4's score is `'101 points'`.
  - `standingsOf uses the game's hook`.
  - `standingsOf falls back when the hook throws` (stub `console.error`, assert it was called).

### Task 2: The manager stamps the game's start and end and reports it once

**Files:**
- Modify: `server/games.ts`, `server/games.test.ts`

**Interfaces:**
- Consumes: Task 1.
- Produces: `ManagerHooks` gains `onGameFinished?: (result: GameResult) => void`. Plans 3 and 10 pass it from `server/server.ts`; this plan passes nothing there.
- Behavior, all in `server/games.ts`:
  - `stamp(room)`, called first in `save`: sets `startedAt = now()` when `state.started` and it is missing; when `state.isGameOver` and `finishedAt` is missing, sets `finishedAt = now()` and calls `onGameFinished` with `archiveId = \`${gameType}/${gameId}#${state.gameNumber ?? 1}\``, `moveCount = room.timeline.length`, `standings = standingsOf(game, state)` `players` = each seat in `activePlayers` with its name (`deviceId` stays unset until plan 10), and `abandoned: true` when the game ended because the platform removed players until fewer than two remained, rather than by the game's own rules (add a test next to `dismissal`). A throwing hook is caught and logged, like `writeStore`.
  - `publicView` adds `startedAt`, `finishedAt`, `gameNumber` and, when `isGameOver`, `standings`, next to `houseRules`, so a game whose `toPublicState` lists its fields still carries them.
  - `resolveUndoVote` carries `startedAt` and `finishedAt` from the live state onto the restored one (with `playerNames`), so a game ended, undone and ended again reports once.
  - `loadRoom` fills a missing `startedAt` (for a started room) and `finishedAt` (for a finished one) with `now()` before its `save`, so a room saved before this change never fires the hook on load.

- [ ] **Step 1: Write failing tests** in `server/games.test.ts`, with a manager built with `hooks.now` stepping and an `onGameFinished` that pushes into an array:

  - `an undo after game over and a second ending report once`: approve an undo of the winning move, move again to win: one result, and `rawState` keeps the first `finishedAt`.
  - `a throwing onGameFinished is logged and the game goes on`: the move still returns a state.
  - `a finished game saved before this change loads without reporting`: save a finished state with no `finishedAt` into an in-memory store, open a new manager on it: no result, `getState` has `finishedAt` and `standings`.
  - `startedAt survives a restart`: equal before and after a reload from the same store.
  - `only a finished game's view carries standings`: `getState` mid-game has no `standings`; after the win it equals the result's standings.

### Task 3: `finalStandings` for every game that keeps a score

**Files:**
- Modify: `games/<id>/rules.ts` (or the game's scoring file named below) and `games/<id>/index.ts` for each game in the table; the game's `rules.test.ts`
- Create: `games/standings.test.ts`

**Interfaces:**
- Consumes: `rankStandings`, `pointsText`, `Standing`.
- Produces: `export function finalStandings(state: GameState): Standing[]`, registered as `finalStandings` in each game's `index.ts`. Each is a call to `rankStandings` with the game's comparison and score text, and must never throw on any state of its game (read optional parts with a default).

| Game | Rank by (best first) | Score text |
|---|---|---|
| Azul | `boards[seat].score`, high | `pointsText` |
| Backgammon | winner only (fallback places) | winner: `pointsText(pointsWon)` |
| Carcassonne | `scores`, high | `pointsText` |
| Catan | `points(state, seat)` (`state.ts`), high | `'<n> victory points'` |
| Dominoes | `scores`, the game's own direction | `pointsText` |
| Euchre, Rook, Spades | the seat's team in `scores` (`teamOf`), high | `pointsText` of the team |
| Farkle, Scrabble, Racko, Uno | `scores`, high | `pointsText` |
| Go Fish | `books[seat].length`, high | `plural(n, 'book')` |
| Hearts | `scores`, low | `pointsText` |
| Texas Hold'em | `chips`, high | `'<n> chips'` with `toLocaleString` |
| Mancala | stones in `bankOf(seat)`, high | `plural(n, 'stone')` |
| Monopoly | not bankrupt first, then later in `bankrupt` ranks higher | losers: `'Bankrupt'` |
| Parchisi | pawns at `HOME`, high | `'<n> of 4 pawns home'` (use the real pawn count) |
| Phase 10 | `phases`, high, then `scores`, low | `'Phase <n>, <points>'`, or `'All phases, <points>'` at 11 |
| Risk | not eliminated first, then later in `eliminated` ranks higher | losers: `'Eliminated'` |
| Rummikub | the round's `result` points, high | signed points, `'+12 points'` / `'-7 points'` |
| Skip-Bo | `stocks[seat].length`, low | `'<n> left in stock'` |
| Splendor | `prestige(players[seat])`, high | `'<n> prestige'` |
| Ticket to Ride | `final[seat].total`, high (0 when `final` is null) | `pointsText` |
| War | `piles[seat].length`, high | `plural(n, 'card')` |
| Yahtzee | the grand total the game ranks by, high | `pointsText` |

Chess, Checkers, Connect Four, Quoridor and The Crew keep the fallback (winner and loser, or the whole crew).
