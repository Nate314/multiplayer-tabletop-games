# Reactions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any player taps another player's name in the presence bar and sends one emoji; everyone sees "Ann → Bo 😂" beside Bo's name for 3 seconds, Bo hears a soft sound, the sender waits 15 seconds, and the reaction is kept in History, the exported file and playback.

**Architecture:** A `REACT` message goes to `manager.react`, which checks the sender, target, emoji (`shared/reactions.ts`) and a per-sender cooldown, appends the reaction with the current `moveCount` to a log on the live state, and returns it; `server.ts` broadcasts a `REACTION` message to the room. The log is stripped from every view and from the undo `history` and `timeline` snapshots, so it never touches undo, the move count or turn order, and it is saved and restored with the live state. History steps gain an optional `reactions` field built from the log, so file version 2 is unchanged and old files load as before.

**Tech Stack:** TypeScript, ws, React 19, SCSS, `Intl.Segmenter`, Unicode property regexes, node:test, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-25-spectators-social-and-new-games-design.md` (feature 6). Index plan: `docs/superpowers/plans/2026-10-25-spectators-social-and-new-games.md`. Branch `reactions` from master, PORT 3106, E2E_PORT_BASE 6210.

## Global Constraints

All of the index plan's Global Constraints, plus:

- Message shapes are the index plan's contract, exactly: client `{ type: 'REACT', payload: { target: Seat; emoji: string } }`; server `{ type: 'REACTION', payload: Reaction }` with `type Reaction = { from: string; fromSpectator: boolean; target: Seat; emoji: string; at: number }`. The recorded form adds `moveCount: number`.
- `REACTION_COOLDOWN_MS = 15_000`, per sender, enforced on the server. `REACTION_SHOW_MS = 3000`.
- Bubble copy: `<from> → <target name> <emoji>`; a spectator sender reads `<from> (watching) → ...`. The arrow is U+2192.
- Error copy, verbatim: `Send a single emoji`, `Pick another player to react to`, `That player is not in this game`, `You can react again in <n> s` (n rounded up).
- A reaction is not a move: no change to `history`, `timeline`, `moveCount`, `currentPlayer`, `undoAvailable`, votes or deadlines.

## Review Focus

1. Undo after a reaction loses the reaction, or brings back a stale log, because the restored state is an old snapshot: Task 2 test `an undo keeps reactions and moves later ones back to the remaining step`.
2. A long game's log grows without bound in every saved state write: the log is capped at `MAX_REACTIONS = 200` (oldest dropped, with a `shortcut:` comment), pinned in Task 2.
3. A reaction leaking hidden state or the log riding along in every `GAME_STATE` view: Task 2 asserts no `reactions` key on any live view or undo snapshot.
4. A hand-edited or old game file whose steps have no `reactions`, or a non-array there, breaking playback: Task 4 `reactionsOf` tests.
5. The presence bar, now always shown in a game with two or more players, crowding phones at 320 px or covering the board: browser check in Task 3, full e2e run in Task 5.

### Task 1: One emoji, validated

**Files:**
- Create: `shared/reactions.ts`, `shared/reactions.test.ts`

**Interfaces:**
- Produces: `REACTION_COOLDOWN_MS`, `REACTION_SHOW_MS`, `MAX_REACTIONS = 200`, the `Reaction` type and `type RecordedReaction = Reaction & { moveCount: number }`, and `isSingleEmoji(text: unknown): boolean`.
- `isSingleEmoji`: a string of at most 32 UTF-16 units, exactly one grapheme by `new Intl.Segmenter(undefined, { granularity: 'grapheme' })`, and that grapheme either matches `new RegExp('^\\p{RGI_Emoji}$', 'v')` or starts with `\p{Extended_Pictographic}` (so an emoji newer than the server's Unicode data, or a bare `❤` without U+FE0F, still passes). Build the `v` regex with `new RegExp` because the tsconfig target is ES2022 and a `/.../v` literal fails the type check.

### Task 2: `react` on the game manager and the `REACT` message

**Files:**
- Modify: `shared/types.ts` (`reactions?: RecordedReaction[]` on `BaseGameState`, comment: the live log, stripped from every view and snapshot), `shared/messages.ts` (`REACT`, `REACTION` types), `server/games.ts`, `server/server.ts`
- Test: `server/games.test.ts`

**Interfaces:**
- Consumes: Task 1.
- Produces: `react(roomId: string, seat: Seat, target: unknown, emoji: unknown): { reaction: Reaction } | { error: string }` on the manager.
  - Order of checks: `findPlayer`; `isSingleEmoji(emoji)`; `target` is in `activePlayers` (else `That player is not in this game`); `target !== seat`; cooldown. Allowed only during play, from the first move until the game is over (the user asked for reactions "during game play"); otherwise `Reactions open once the game starts`.
  - The cooldown lives on the room, not in the state: `lastReactionAt: Map<string, number>` keyed by a sender key (`seat:<n>` now; plan 1's merge adds `spectator:<id>`), so a restart clears it.
  - On success it appends `{ ...reaction, moveCount: room.timeline.length }` to `state.reactions` (keeping the last `MAX_REACTIONS`), calls `save(roomId, room)` with no step, and returns the `Reaction` without `moveCount`. `from` is `playerNames[seat]`, `fromSpectator: false`, `at: now()`.
  - `publicView` strips `reactions` along with `seatKeys`. `record()` pushes copies of the before and after states without `reactions` into `history` and `timeline`. The undo restore in `resolveUndoVote` sets `reactions` from the live state, with each `moveCount` above the new `room.history.length` lowered to it.
  - Integration with plan 1: a spectator branch builds `from: spectator.name, fromSpectator: true` with key `spectator:<id>`; the target rules and cooldown are shared. No other change.
- `server.ts`: `case MESSAGE_TYPES.REACT` calls `manager.react(roomId, seat, payload?.target, payload?.emoji)`; on error `sendError`; on success `broadcastReaction(roomId, reaction)`, which sends `{ type: REACTION, payload: reaction }` to every connection in the room. No `GAME_STATE` broadcast.
- `gameService.ts`: `react(target: Seat, emoji: string): void` and `onReaction: ((reaction: Reaction) => void) | null`, handled in `handleMessage`.

- [ ] **Step 1: Write the failing tests** in `server/games.test.ts`, with the manager's `now` hook set to a counter the test advances:

**Interfaces:**
- Consumes: the live log from Task 2, `reactionLabel` from Task 3.
- Produces:

With Sounds on, stepping forward onto a step with reactions plays nothing extra (reactions are not move sounds).
