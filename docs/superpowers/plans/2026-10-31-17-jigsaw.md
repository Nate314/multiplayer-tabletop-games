**Goal:** Add Jigsaw (`jigsaw`, Puzzles): put a picture back together from 24, 48, 96 or 150 pieces, alone (Solo), on one shared board (Together) or in a Race on identical copies, with 8 built-in SVG pictures or an uploaded photo.

**Architecture:** A new game folder `games/jigsaw/` on the `GameDefinition` contract, built on chunk 0 (`shared/puzzleModes.ts`, `continuesAlone`, `undoOwn`, `imagesOf`, the image routes and `src/services/images.ts`). Every piece interaction is a game action in every mode: pick-up and a loose drop update state unrecorded, a drop that lands on the piece's true spot snaps, locks and is recorded. Piece shapes are never sent: client and server both derive them from a `seed` in state through the shared `games/jigsaw/cut.ts`. The state holds only a picture reference (a built-in name or an uploaded image id), so broadcasts stay small.

**Tech Stack:** React 19, TypeScript, SCSS, SVG (`clipPath` and `<image>`), Pointer Events, node:test, Playwright.

## Review Focus

1. Two players in Together press the same loose piece within a few milliseconds: the second pick-up is refused, the first holder keeps it, and the second player's screen snaps the piece back without a stuck ghost (Task 3 test `'a held piece cannot be taken'`, Task 5 drag test, Task 7 e2e).
2. A player holding a piece disconnects, leaves or is dismissed: the piece is released where it lay so nobody else is locked out of it forever (Task 3 tests on `onPlayerDisconnected` and `onPlayerLeft`).
3. A Race player reads another board through History, a game file, the table screen or raw WebSocket frames during play: only percentages reach them (Task 4 view tests, Task 7 frame test).
4. A crafted action with a piece index out of range, a fractional or huge `x`, `NaN`, a malformed image id, or a drop on a piece someone else holds: refused with a message, state unchanged (Task 3 validation test).
5. Solo undo after loose pieces were moved since the last snap: the snap is taken back, no piece is left held, and the README says loose moves since the previous snap return to where they were (Task 3 `onUndo` test, README).

### Task 2: The cut: grid, tab and blank edges, table layout, snapping

**Files:**
- Create: `games/jigsaw/cut.ts` (imported by rules and client), `games/jigsaw/cut.test.ts`

**Interfaces:**
- Consumes: `PICTURE_W`, `PICTURE_H` from Task 1.
- Produces:
  ```ts
  export type PieceCount = 24 | 48 | 96 | 150;
  export const GRIDS: Record<PieceCount, { cols: number; rows: number }>; // per Global Constraints
  export const TABLE_W = 2000, TABLE_H = 1800, BOARD_X = 280, BOARD_Y = 80; // table units; the board is PICTURE_W x PICTURE_H
  export type Grid = { cols: number; rows: number; w: number; h: number }; // w, h: one cell in table units
  export function gridOf(count: PieceCount): Grid;
  export function homeOf(grid: Grid, piece: number): { x: number; y: number }; // the cell's top-left on the board; piece = row * cols + col
  // +1: a tab out of the piece toward +x or +y; -1: a blank. Outer sides are flat (0)
  export type Edges = { right: number[][]; down: number[][] }; // right[row][col] for col < cols-1, down[row][col] for row < rows-1
  export function edgesOf(seed: number, grid: Grid): Edges;
  export function piecePath(grid: Grid, edges: Edges, piece: number): string; // SVG path in piece-local units, (0,0) the cell's top-left
  export const SNAP_FRACTION = 0.3;
  export function snaps(grid: Grid, piece: number, x: number, y: number): boolean; // distance to home <= SNAP_FRACTION * min(w, h)
  export function clampToTable(grid: Grid, x: number, y: number): { x: number; y: number }; // whole numbers, cell fully on the table
  export function scatter(grid: Grid, random: Random): { x: number; y: number }[]; // one start spot per piece
  ```

Edge note (the one algorithm the signatures leave open): `edgesOf` draws each inner edge's sign from a mulberry32 random seeded with `seed` (in a fixed order: all `right`, then all `down`), so the same seed always gives the same cut on client and server. `piecePath` walks the four sides clockwise; a flat side is a line, an inner side is a line to 35% of its length, a tab head of two cubic curves bulging 22% of the cell's shorter side outward (sign +1 on the right and bottom sides of the piece, inverted on the left and top since those are the neighbor's edges), then a line to the corner. `scatter` picks spots uniformly at random with the cell wholly on the table and not overlapping the board rectangle grown by the tab size, retrying up to 20 times and keeping the last try.

  export type Piece = { x: number; y: number; placed: boolean; heldBy: Seat | null; placedBy: Seat | null };

- Produces (`rules.ts`, wired in `index.ts` as `jigsaw: GameDefinition<GameState, PublicGameState>` with `continuesAlone: true`): `createGameState`, `resetLobby`, `applyAction`, `recordsAction`, `onUndo`, `undoOwn`, `onPlayerLeft`, `onPlayerDisconnected`, `imagesOf`, `boardOf(state, seat): Board | undefined`. `applyMove` always answers `{ error: 'Use the pieces on the table' }`.
- Actions:
  - `{ type: 'setPicture', picture: Picture }`: only the house rules host (`houseRulesOf(info, state).host`), only before `started` (`'The picture is fixed once play starts'`), a known built-in name or a well-formed id (`'That picture is not available'`). Changes only `picture`.
  - `{ type: 'pickUp', piece: number }`: on the seat's own board (Race) or the shared one; refused when placed (`'That piece is locked in place'`) or held by another (`'<name> is holding that piece'`). A seat holds one piece; a piece it already held is released where it lies. The first pick-up sets `started: true`, so the platform's agreement gate and the join lock apply and the picture locks. Not recorded.
  - `{ type: 'drop', piece: number, x: number, y: number }`: only by its holder (`'You are not holding that piece'`). Finite numbers only, then `clampToTable`. When `snaps`, the piece moves to `homeOf`, `placed: true`, `placedBy: seat`, pushes onto `snaps[seat]`, `addContribution`, `lastMove: snap`; else it lies loose at the clamped spot.
  - Every action after `isGameOver` is refused with `'The puzzle is finished'`; non-integer or out-of-range `piece` with `'No such piece'`.
- `recordsAction(state, seat, action)`: true exactly when `applyAction` would snap (the same validation, then `snaps`).
- Game end: Solo and Together when every piece of `board` is placed (`isGameOver`, `winners` every active seat, status `The puzzle is done!`); Race when a seat's board is complete (`winners: [seat]`, status `<name> finished first!`).
- `resetLobby`: reads `count` from `PIECES_RULE` and the mode with `modeOf(state, MODE_RULE)`, draws a new `seed`, scatters once with `random`, gives Race seats identical copies, keeps `picture`, empties `snaps`, `contributions`, `lastMove`.
- `onUndo` (Solo's normal undo restores the state before the snap, where the piece was still held): clears every `heldBy`.
- `undoOwn(state, seat)`: pops the seat's last snap; that piece becomes loose at its home offset by half a cell right and down (clamped), `placedBy: null`, contribution down by one, `lastMove: unsnap`. None left: `{ error: 'Nothing of yours to undo' }`. Refused after game over by the platform.
- `onPlayerLeft` and `onPlayerDisconnected`: release any piece the seat holds where it lies; `onPlayerLeft` also deletes the seat's Race board and snaps. The game goes on with whoever is left.
- `imagesOf(state)`: `[picture.id]` for a photo, else `[]`.
