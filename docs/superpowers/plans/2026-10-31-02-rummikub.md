# Rummikub: Sort Replay, Strict Jokers, Two House Rules and Save Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A sorted rack no longer slides again on the next move, the strict joker rule matches the official rules, two house rules (Jokers move freely, Add to melds on your first turn) are offered, and a player can Save a valid arrangement that Reset returns to.

**Architecture:** The replay bug is fixed in the animation plumbing: `useMoveAnimation` gains a way to measure again after a change made on the screen, `useLocalSlides` calls it once a local change has rendered, and Rummikub's `animateMove` skips a tile whose place did not change. The rule changes all live in `checkPlay` in `games/rummikub/rules.ts`, which the browser preview and the server share; it takes a new `PlayRules` read from the house rules, declared in a new `games/rummikub/options.ts`. Save is browser-only state in `PlayArea`, with the decisions in pure functions in `draft.ts`.

**Tech Stack:** TypeScript, React 19, node:test, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-31-pause-resume-jenga-and-fixes-design.md`, section 2 (2a to 2e). Index plan: `docs/superpowers/plans/2026-10-31-pause-resume-jenga-and-fixes.md` (Shared contracts, Global Constraints, Combining). Branch `rummikub-rules-and-save` from `pause-resume-jenga-and-fixes`. Server `PORT=3202`, `E2E_PORT_BASE=6430`.

## Global Constraints

All of the index plan's Global Constraints, plus:

- House rule ids and labels are exact: `freeJokers` "Jokers move freely" and `addOnFirstMeld` "Add to melds on your first turn", both `kind: 'toggle'`, `standard: false`.
- The strict joker rule stays the default. With `freeJokers` off and `addOnFirstMeld` off, every play the official rules allow is still accepted.
- Error copy, exactly:
  - `A joker taken from the table must be replaced by the tile it stands for` (no replacing tile anywhere; the existing text)
  - `The tile that replaces a joker must come from your rack` (the only replacing tile came from the table)
  - `A joker taken from the table must be played again with at least two tiles from your rack`
  - `On your first meld you may add tiles to the groups on the table, but not move them` (only with `addOnFirstMeld` on)
- Save button text `Save`, title `Reset comes back to the saved arrangement`. Checkpoints live only in `PlayArea` state: never sent, never stored.
- `useMoveAnimation`'s new return value is optional for callers: the other 31 call sites compile and behave unchanged.
- Rulings this plan makes (list them in the PR): the two rack tiles a freed joker needs do not include the tile that replaced it; one group's two rack tiles may serve every freed joker in that group; a Reset that lands on the start of the turn clears the checkpoint; Reset to a checkpoint restores its rack order exactly; `freeJokers` does not loosen the first meld.
- Tile shorthand in this plan's tests: `r4` is `t('red', 4)`, `b` blue, `k` black, `o` orange, a trailing `'` the second copy (`r5'` is `t('red', 5, 1)`), `J1` and `J2` the jokers, `RED_RUN` the existing red 10, 11, 12. Tests write the `t(...)` calls.
- Contract additions: none outside `games/rummikub`. Overlap to flag at combining: `src/animation/useMoveAnimation.ts` and `src/animation/motion.ts` (plan 6, Scrabble ghost tile, may touch the same animation code).

## Review Focus

1. A joker that changes what it stands for inside its own group (red 4, red 5, joker as red 6, then the red 6 goes on the end) now counts as taken and needs two more rack tiles; the existing e2e test that expects "Ready to play 1 tile" must be changed, not the rule loosened (Task 3).
2. `addOnFirstMeld` letting a first meld change a joker's meaning on the table (adding red 6 after red 4, red 5, joker as red 6 makes the joker a red 7): rejected as a move (Task 5).
3. A rack rearranged by a drag rather than a click: the drop path returns early on `takeDrop()`, and the rack must still be measured again so it does not slide on the next move (Task 2).
4. Save pressed, then the player reorders the rack, then Reset: the checkpoint's table and rack come back, and a second Reset goes to the start of the turn (Task 6).
5. A game saved before the house rules (no `houseRules` field) loads and plays with both rules off, through `houseRule`'s standard values (Task 4).
