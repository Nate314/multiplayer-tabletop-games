# Jenga Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 3D Jenga for 2 to 8 players where the server runs the physics of every pull, each block has a hidden grip, and whoever topples the tower loses.

**Architecture:** A small platform addition lets a game run a live simulation: while `simulating(state)` is true the manager calls `simulate(state)` every 50 ms, broadcasts the result and does not record it. Jenga's pulls are actions (grab, drag, release) that steer a Rapier world on the server; placing the block on top is the one recorded move of a turn. The browser draws the tower with three.js and runs the same Rapier code as a preview between server updates. Both libraries are imported only by `games/jenga/` (the server's game module and the lazy client chunk).

**Tech Stack:** As the index plan, plus `three@0.186.1`, `@dimforge/rapier3d-deterministic-compat@0.21.0` and, for types only, `@types/three@0.186.0`.

**Spec:** `docs/superpowers/specs/2026-10-25-spectators-social-and-new-games-design.md` (feature 12). Index plan: `docs/superpowers/plans/2026-10-25-spectators-social-and-new-games.md`.

Branch `jenga` from master, worktree of its own. PORT 3112, E2E_PORT_BASE 6330.

## Library choices

- **Rapier: `@dimforge/rapier3d-deterministic-compat@0.21.0`** (released 2026-09-25). Since rapier.js 0.15 the plain `rapier3d` packages are built without `enhanced-determinism`; the `-deterministic` flavors keep it, and Rapier documents its WASM build as fully cross-platform deterministic for the same version, the same construction and insertion order, and inputs that avoid `Math.sin`/`Math.cos`. The `-compat` flavor inlines the WASM as base64, so `await RAPIER.init()` works the same in Node 22 (type stripping imports `dist/rapier.mjs` like any ESM package) and in Vite (no wasm plugin, no `?url` asset, no `--experimental-wasm-modules`). Size: `dist/rapier.mjs` is about 4.4 MB unminified, nearly all of it the base64 WASM; expect well over 1 MB gzipped in the Jenga chunk. It ships its own types. Apache-2.0.
- **three.js: `three@0.186.1`** (released 2026-09-24). Only the core (`three`), no `three/addons`: the orbit camera is written here, because a press on a block must pull while a press on empty space orbits, which is simpler to own than to arbitrate with `OrbitControls`. MIT.
- **`@types/three@0.186.0`** (2026-09-11), a dev dependency, since three ships no types. It is types only and never bundled.
- All three pinned exactly (`--save-exact`). Rapier and three go in `dependencies`, like React, because the server imports Rapier at runtime.

## Global Constraints

All of the index plan's Global Constraints, plus:

- `three` and `@dimforge/rapier3d-deterministic-compat` are imported only from `games/jenga/physics.ts`, `games/jenga/index.ts` and `games/jenga/client/**`. Nothing in `src/`, `shared/`, `server/` or another game imports them, or imports `games/jenga/physics.ts`.
- The main bundle (`dist/assets/index-*.js`) grows by under 1 KB against master (the loader line and the info), and no file but the Jenga chunk contains `WebGLRenderer` or `RAPIER`.
- Block grip (`grip`) never leaves the server: not in any view, history step, game file or e2e page. Block colors never depend on grip.
- Physics code never calls `Math.sin`, `Math.cos`, `Math.random` or `Date.now`; the quarter-turn quaternion is the constant `[0, Math.SQRT1_2, 0, Math.SQRT1_2]`. Bodies are always created in `blocks` array order.
- Units are centimetres, grams and seconds: gravity `(0, -981, 0)`, `world.lengthUnit = 100`, fixed `world.timestep = 1 / 60`.
- No house rules for Jenga.

## Decisions (read before any task)

**Tower.** Block 7.5 long, 1.5 high, 2.5 wide; density 0.6 (about 17 g). 18 levels of 3; level `k` has its center at `y = 1.5 * (k + 0.5)`. Even levels run along X (blocks at `z = -2.5, 0, 2.5`), odd levels along Z (at `x = -2.5, 0, 2.5`, quaternion the constant above). Ids 0 to 53 in level then slot order. A fixed ground cuboid with its top at `y = 0`, friction 0.6. Footprint: the square `|x|, |z| <= 3.75`.

**Grip.** Each block's friction is `0.35 + 0.3 * random()`, rounded to 2 places, drawn in `resetLobby` (the platform's `Random`; `createGameState` has none and uses 0.5 for all). Kept in `grip: number[]` by block id. The client preview uses 0.5 for every block.

**Pull input.** `grab { block, anchor }` (anchor in block-local coordinates, within the half extents), `drag { target: [x, y, z] }` (world; `y` is ignored and set to the anchor's height), `release {}`. Each substep the server applies the impulse `clamp(PULL_STIFFNESS * mass * gap - PULL_DAMPING * mass * anchorVelocity, MAX_PULL_FORCE) * dt` at the anchor, `gap = target - anchorWorld`. A fast drag gets the target further ahead, so the force grows with drag speed up to the cap. The target is clamped to within `MAX_REACH = 3` of the anchor. Starting values: `PULL_STIFFNESS = 400`, `PULL_DAMPING = 40`, `MAX_PULL_FORCE = 600000` (about 6 N); Task 1's tests bound them. Pushing back in uses the same spring, so sliding a block back is just dragging it back. Releasing and grabbing a different block is choosing another; any number of times per turn.

**Legal pulls.** Blocks keep the `level` they were placed at. The top level is the highest level with a block. A block may be grabbed only below the top level, and only below the level under it while the top level has fewer than 3 blocks.

**Out of the tower.** While grabbed, a block whose bounding box no longer overlaps the footprint is taken out: removed from the world, `held` set, phase `place`. A released last-pulled block that comes to rest on the ground (center `y < 1.5`) outside the footprint also counts as taken out.

**Topple rule.** At any tick, the tower has toppled if any block other than the last pulled block (`pull.block`) has its center more than 0.75 below where it was at the start of the turn, or is tilted more than 30 degrees from its turn-start orientation (`2 * acos(|q0 . q1|)`; fine on the server, it only decides, it never feeds the physics). The same check runs after a placement.

**Turn and recording.** Grab, drag and release are actions (never recorded). `place { slot: 0 | 1 | 2 }` is the move: it is refused until the tower is at rest (`Wait for the tower to settle`). It fills an empty slot of an incomplete top level, or starts a new level at a quarter turn when the top is full, puts the block 0.01 above its resting height, steps the world synchronously until at rest (at most 180 steps), and records one move. The topple ends the game on the tick the collapse comes to rest (or after 100 ticks): that tick turns `isGameOver` true, which the manager records as a move, like a deadline. So History is: the start, one step per placed block, and a final "toppled the tower" step showing the fallen blocks.

**Rest.** At rest when nobody holds a grab and every body is sleeping or under 0.5 cm/s and 0.05 rad/s for 10 ticks in a row, or 200 ticks (10 s) after the last release. Then `sim` is null and velocities are dropped.

**History.** `lastMove` is `{ type: 'place'; seat; block; from: Pose; to: Pose; level }` or `{ type: 'topple'; seat }`. The previous History step is the tower before; the `HistoryBoard` draws the step's tower with a translucent ghost at `from` and the placed block highlighted at `to`, so one frame shows before and after.

**Disconnect, leave, undo, restart.**
- `onPlayerDisconnected`: if the seat holds a grab, it is dropped and the tower settles (a topple then still counts against them). A block already in hand stays in hand for when they return.
- `onPlayerLeft` (dismissal): if `pull.seat` is the seat that left, the tower goes back to `turnStart`, nobody holds anything, `sim` null.
- `onUndo`: the restored state goes back to its own `turnStart` (`held`, `grab`, `pull`, `toppled` cleared, `sim` null), so an undo always undoes a whole turn, and undoing a topple restores the toppler's turn start.
- `resumeClock` (runs after a restart, after an undo and on the last house rules agreement): clears `grab`; if `sim` is set it keeps settling from the saved poses.

**Wire size.** Views round positions to 3 decimals and quaternions to 4, and include velocities only for moving blocks. `grip` and `turnStart` are stripped.

**Standings.** `jengaStandings(state)`: the loser at place 2 with score `Toppled the tower`, everyone else at place 1 with `<n> blocks placed` (`plural`). Plan 2's `finalStandings` hook is not on master, so it is exported now and wired when combining (see Task 6).
