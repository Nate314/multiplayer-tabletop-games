# Turn Timer House Rule Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every game offers an optional "Turn timer" house rule (off, 30 seconds, 1, 2 or 5 minutes) that counts down beside the current player in the presence bar and only warns when time runs out.

**Architecture:** The rule is declared once in `shared/houseRules.ts` and appended to every game's own rules by a `rulesOf(info)` helper, so no `options.ts` changes. Games with their own enforced turn limit opt out with `GameInfo.ownTurnLimit?: true` (Pictionary sets it when the waves are merged); `rulesOf` skips the timer for them. The server stamps `turnStartedAt` (and a pause mark) on the live state in the manager's one save path; it never schedules a timer, never calls `onDeadline` and never records anything, so the undo timeline is untouched. Clients compute the time left, the red last 10 seconds, the tick, "Time's up" and the overtime from the stamp and `serverTime`.

**Tech Stack:** TypeScript, node:test, React 19, SCSS, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-25-spectators-social-and-new-games-design.md`, feature 7. Index: `docs/superpowers/plans/2026-10-25-spectators-social-and-new-games.md`. Branch `turn-timer` from master, PORT 3107, E2E_PORT_BASE 6230.

## Global Constraints

All of the index plan's Global Constraints, plus:

- The rule: id `turnTimer`, label `Turn timer`, values `0 | 30 | 60 | 120 | 300` (seconds), standard `0`; choice labels `Off`, `30 seconds`, `1 minute`, `2 minutes`, `5 minutes`; help `A warning only: nobody's turn is skipped.`
- `turnStartedAt?: number | null` on `BaseGameState` (index contract). This plan adds one more optional field, `turnPausedAt?: number | null`, needed to pause during votes (reported to the index owner).
- Running out is a warning only. Nothing is recorded, skipped or passed, and no `deadline` / `onDeadline` / `resumeClock` hook is used for it.
- Copy, exact: current player `Time's up`; others `<name> is over time`; overtime clock `+m:ss`; paused clock keeps its value and adds ` (paused)`.
- A game without its own house rules still starts without anyone pressing Agree while the timer is Off. Setting it on makes everyone agree, like any rule.
- Scrabble's own rule (`turnMinutes`, which passes the turn) is relabeled `Turn limit` so the two controls have distinct labels.

## Review Focus

1. A saved room or game file from before this change (no `turnTimer` value, no `turnStartedAt`) loads, plays and shows no timer (Task 1, Task 2).
2. An undo, a dismiss vote passing, or a restart while the timer runs: the restored or next player gets a fresh full turn, never a negative clock inherited from the old state (Task 2).
3. Two moves in a row by the same player (Catan building) do not restart the clock; the next player's turn does (Task 2).
4. The timer at zero changes nothing on the server: no move count change, no history step, no status change, and play continues (Task 2, Task 4).
5. A view with the timer Off is byte-for-byte what it was before (no `turnStartedAt` key added), so existing deep-equal tests and exported files are unchanged (Task 2).

### Task 2: The server stamps the turn, pauses for votes, never records

**Files:**
- Create: `shared/turnTimer.ts`, `shared/turnTimer.test.ts`
- Modify: `shared/types.ts` (the two optional fields, with one-line comments), `server/games.ts`
- Test: `server/games.test.ts`

**Interfaces:**
- Consumes: `TURN_TIMER`, `houseRule` (Task 1).
- Produces in `shared/turnTimer.ts`:
  - `turnLimitMs(state: Pick<BaseGameState, 'houseRules'>): number` (0 when off).
  - `votePauses(state: BaseGameState): boolean`, true while `undoVote` or `dismissVote` is open. This is the one list of pausing votes; plan 3 adds `rematchVote` here when merged. Hand requests never pause the timer (they involve two people only).
  - `stampTurn(state: BaseGameState, clockSeat: Seat | null | undefined, running: boolean, now: number): { state: BaseGameState; clockSeat: Seat | null }`. Rules, in order: not `running` or timer off: clear both fields (leave them absent if absent) and return `clockSeat: null`. `currentPlayer !== clockSeat` or `turnStartedAt` null/absent: `turnStartedAt = now`, `turnPausedAt = votePauses ? now : null`. Vote open and not paused: `turnPausedAt = now`. No vote and paused: `turnStartedAt += now - turnPausedAt`, `turnPausedAt = null`. Otherwise unchanged (same object).
  - `turnTimeLeft(state: Pick<BaseGameState, 'houseRules' | 'turnStartedAt' | 'turnPausedAt'>, now: number): number | null`, `limit - ((turnPausedAt ?? now) - turnStartedAt)`, negative in overtime, null when off or unstamped.
- Room gains `clockSeat?: Seat | null` (memory only). `save()` calls `stampTurn(room.state, room.clockSeat, running, now())` before writing, where `running = turnLimitMs(state) > 0 && !state.isGameOver && clockMayRun(room) && state.currentPlayer !== null`.
- `publicView` copies `turnStartedAt` and `turnPausedAt` onto the view only when the state has them (so a game whose `toPublicState` builds a fresh object still passes them, and an Off game's view gains no key).
- `resolveUndoVote` sets `turnStartedAt: null` on the restored state, and `loadRoom` sets `turnStartedAt: null, turnPausedAt: null`, so both restart at `now` (a fresh full turn; the downtime is never charged).
