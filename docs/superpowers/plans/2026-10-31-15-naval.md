**Goal:** Add Naval Battle (`naval`), the traditional pencil-and-paper grid naval game for 2 players: each places a secret fleet on a 10x10 grid, then they take turns firing until one fleet is sunk, with a Salvo house rule.

**Architecture:** A new `games/naval/` folder on the existing `GameDefinition` contract, built like Chess (2 players, resign and draw offers through `shared/drawOffer.ts`, the remaining player wins on leaving) with a Hearts-style simultaneous setup: placing a fleet is an unrecorded game action that sets `started`, and play begins once both seats have confirmed. Firing is a move. The fleets live only in the raw state; `toPublicState` gives each seat its own fleet (`myFleet`), gives everyone the shots and their results, and shows every fleet (`revealed`) only once the game is over. `privateSeatView` is exactly `myFleet`, so a spectator sees a fleet only with that seat's permission.

**Tech Stack:** React 19, TypeScript 5.9, SCSS, node:test, Playwright. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-31-nine-new-games-design.md`, sections "Rules for every game agent" and "Naval Battle". Wikipedia: [Battleship (game)](https://en.wikipedia.org/wiki/Battleship_(game)), the traditional pencil-and-paper game.

**Branch:** `game-naval`, in its own worktree, from `nine-new-games`. PR into `nine-new-games`. Server `PORT=3415`, `E2E_PORT_BASE=6740` (never 6000).

## Global Constraints

- **Naming.** The game is "Naval Battle", id `naval`. The word "Battleship" and any Hasbro or Milton Bradley name appear nowhere in code identifiers, copy, FAQ, README or commit messages; the README cites the Wikipedia article only by its URL in a link labeled "Wikipedia's article on the traditional grid naval game". Ships have no names: they are known by length ("a ship of length 3").
- **Rules (exact):** grid 10x10, rows A to J top to bottom, columns 1 to 10 left to right, a square named like `B7`; fleet lengths `[5, 4, 3, 3, 2]`; horizontal (`across`) or vertical (`down`), inside the grid, not overlapping, touching allowed; one shot per turn; the answer is miss, hit, or hit and sunk with the length named; no extra shot for a hit; seat 1 fires first; sinking every enemy ship wins.
- **Salvo (exact):** `SALVO: ToggleRule = { id: 'salvo', label: 'Salvo', kind: 'toggle', standard: false, help: 'Each turn, fire one shot per ship you still have afloat' }`, in `games/naval/options.ts`. Shots per turn are counted from the shooter's own fleet at the start of the turn, capped at the number of squares they have not yet fired at. Each shot's result is shown.
- **Hidden fleets.** Before game over, no fleet reaches any browser except its owner's: not the other seat, not `viewer: null` (History, table screen), not a spectator without that seat's permission, not a pause file of the other seat, not `lastMove`, `gameStatus` or an error message. A sunk ship's squares are not revealed either (only its length, on the shot that sank it). After game over every view has `revealed` with both fleets. An undo never reveals a ship: the restored state's views hide exactly what they hid before the undone move.
- **No `secretState`.** Each fleet is visible to its owner, so it is per-seat (`privateSeatView`), not hidden from every player; `games/secretState.test.ts` is unchanged. No `onUndo` (nothing random to reshuffle).
- **Placement is an action, not recorded** (`recordsAction` absent). Confirming a fleet sets `started: true`. A confirmed fleet cannot be changed. The draft fleet lives in the browser only until Confirm.
- **Endings:** `applyEndingAction` from `shared/drawOffer.ts` (resign, offer and answer a draw), `lapseDrawOffer` after each fire move, `DrawAndResign` from `src/components/`. Leaving: the platform's 2-player rule (the remaining player wins); no `onPlayerLeft`. Standings: the platform fallback (no `finalStandings`).
- **Copy (exact):** statuses `Place your fleets`; `<name> is ready`; `Both fleets are ready. <name> fires first`; `<name> fired at B7: miss` / `hit` / `sank a ship of length 3`; for a salvo `<name> fired at B7, C7 and D7: hit, miss, sank a ship of length 3`; win `<name> sank every ship. <name> wins!`. Refusals `Waiting for another player`, `Your fleet is already placed`, `Place one ship of each length: 5, 4, 3, 3 and 2`, `A ship goes off the grid`, `Ships cannot overlap`, `Wait for both fleets to be placed`, `Fire at 1 square` / `Fire at <n> different squares`, `That square is off the grid`, `You already fired there`, `The game is over`, `A vote is in progress`. Buttons `Rotate`, `Random placement`, `Clear`, `Confirm fleet`, `Fire`.
- **Files outside `games/naval/`** (one entry each; list them in the PR so the coordinator can merge them): `games/registry.ts`, `games/infos.ts`, `src/clientGames.ts`, `shared/svg/gameIcons.ts` (a `naval` icon, required by `src/games/loadClientGame.test.ts`), `shared/categories.test.ts` (`naval` in `classic`, count 33 to 34), `games/standings.test.ts` (`naval` in `FALLBACK_GAMES`), `games/privateSeatView.test.ts` (a `naval` entry in `CASES`), `e2e/landing.spec.ts` (card count 33 to 34), `README.md` (game list and its count), `docs/architecture.md` (the house rules list and the Hidden state paragraph), and `e2e/naval.spec.ts`. ## Review Focus

1. Salvo late in the game with fewer unfired squares than ships afloat: the shot count is capped, so the player can still fire and the game cannot stick (Task 2: `'a salvo is capped at the squares left'`).
2. A player resigns or leaves after one fleet is confirmed and before the other is: the game ends with the other player winning, `revealed` holds only the confirmed fleet, and every view still renders (Task 2: `'resigning during placement ends the game with one fleet revealed'`; Task 4 HistoryBoard handles a missing fleet).
3. A refresh or rejoin after confirming: the screen shows the confirmed fleet and "Waiting for <name>", not an empty placement step (Task 3: `'a rejoin after confirming gets the confirmed fleet back'`).
4. Pass and play on one device: during placement both seats must act, so the handoff must hide one fleet before the other is placed (Task 2: `'waitingOn lists every seat still placing'`; the platform hides the shown seat once another is waited on).
5. Placing by touch on a phone: dragging a ship must move the ship, not scroll the page, and a tap-then-tap path must work too (Task 5: `'a ship can be placed by touch'` in `e2e/naval.spec.ts`, plus the 390 px browser check).

  export type Cell = { row: number; col: number }; // 0..9; row 0 is A, col 0 is 1

  export type Shot = { row: number; col: number; result: 'miss' | 'hit' | 'sunk'; sunkLength?: ShipLength };
  export type Phase = 'placing' | 'firing';
  export type LastMove = { type: 'fire'; playerNumber: Seat; shots: Shot[] };
  export type Move = { type: 'fire'; targets: Cell[] };
  export type Action = { type: 'place'; ships: Ship[] } | EndingAction;
  export type GameState = BaseGameState & DrawOfferState & {
    phase: Phase;
    fleets: Partial<Record<Seat, Ship[]>>; // confirmed fleets only; never in a view before game over
    shots: Record<Seat, Shot[]>;           // shots fired BY each seat, in order
    lastMove: LastMove | null;

    ready: Seat[];                           // seats whose fleet is confirmed
    myFleet: Ship[] | null;                  // the viewer's own confirmed fleet; null for viewer null or not yet confirmed
