**Goal:** Add Sudoku (`sudoku`, Puzzles category) for 1 to 8 players, with Solo, Together and Race modes, an Easy, Medium or Hard puzzle generated on the server with exactly one solution, digits and per-player pencil marks, and a solution that no browser sees before the game ends.

**Architecture:** A new folder `games/sudoku/` on the `GameDefinition` contract plus chunk 0's `shared/puzzleModes.ts`. A pure, seeded generator (`generator.ts`) builds the puzzle in `resetLobby`. Solo entries are moves; Together and Race entries are recorded actions (`recordsAction`), taken back one seat at a time with `undoOwn`. `toPublicState` strips the solution, other seats' Race boards and other seats' pencil marks; `secretState` names the solution.

**Tech Stack:** TypeScript, React 19, SCSS, node:test, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-31-nine-new-games-design.md` (sections "Shared ground", "Rules for every game agent" and "Sudoku"). Builds on `docs/superpowers/plans/2026-10-31-10-shared-puzzle-modes.md` (chunk 0), whose Interfaces blocks give every shared name used here.

## Review Focus

1. A Race move's `lastMove` (cell and digit), `gameStatus` or `describeMove` text reaches another seat or History (`viewer: null`) and gives away that seat's board: views strip `cell` and `digit` from another seat's move during play (Task 3 test `a Race move shows others only who moved`).
2. Together: Bob writes a wrong 4, Alice overwrites it with the right 7, then Bob presses Undo my last move: Bob's stale move is skipped and Alice's 7 stays (Task 2 test `undoOwn skips a move a friend has since replaced`).
3. Untrusted input: `cell` 81, -1, 1.5 or `'3'`, `digit` 0, 10 or `'5'`, an unknown `type`, and an action after game over are refused with an error and change nothing (Task 2 test `bad cells, digits and types are refused`).
4. A full Race board that is wrong: the game goes on, only its owner gets `boardWrong: true`, and any later entry, erase or undo on that board clears it (Task 2 test `a full wrong Race board tells only its owner`, Task 3 view assertion).
5. Solo with Show mistakes off: the view has no `wrong` field at all, so a player cannot read it from the frames (Task 3 test `Solo shows mistakes only while the toggle is on`).

**Files:**

**Interfaces:**
- Consumes (chunk 0): `MODE_RULE: ChoiceRule<PuzzleMode>` from `shared/puzzleModes.ts`.
- Produces (`options.ts`): `type Difficulty = 'easy' | 'medium' | 'hard'`; `DIFFICULTY: ChoiceRule<Difficulty>` with id `difficulty`, label `Difficulty`, `standard: 'medium'`, choices `Easy`, `Medium`, `Hard`, help `Easy needs only singles; Medium has fewer givens; Hard needs more than singles.`; `SUDOKU_RULES: HouseRule[] = [MODE_RULE, DIFFICULTY]`.
- Produces (`info.ts`): `sudokuInfo: GameInfo`, `id: 'sudoku'`, `name: 'Sudoku'`, `category: 'puzzle'`, description `Fill the grid so every row, column and box holds 1 to 9, alone, together or as a race`, 1 to 8 players, `houseRules: SUDOKU_RULES`.
- Produces (`grid.ts`, imported by client and server, imports nothing secret): `CELLS = 81`; a grid is `number[]` of length 81, index `row * 9 + col`, `0` empty; `rowOf(cell)`, `colOf(cell)`, `boxOf(cell)`, `peers(cell): number[]` (the 20 cells sharing a row, column or box), `cellName(cell): string` (`'row 3, column 5'`, 1-based).
- Produces (`generator.ts`, server side; no client file imports it):
  - `fullGrid(random: Random): number[]`
  - `countSolutions(grid: readonly number[], limit: number): number` (stops at `limit`)
  - `solvesWithSingles(grid: readonly number[]): boolean`
  - `generatePuzzle(difficulty: Difficulty, random: Random): { givens: number[]; solution: number[] }`
  - `GIVENS = { easy: 36, medium: 30 } as const`

Generator note (the one algorithm the tests do not determine):
- `fullGrid`: backtracking over cells in order, trying digits in `shuffle([1..9], random)` order (`shared/shuffle.ts`), with row, column and box bitmasks.
- `countSolutions`: backtracking that always branches on the empty cell with the fewest candidates; returns as soon as `limit` solutions are found. Uniqueness is `countSolutions(g, 2) === 1`.
- `solvesWithSingles`: repeat naked singles (a cell with one candidate) and hidden singles (a digit with one place in a row, column or box) until stuck; true when the grid is full.
- `generatePuzzle`: take `fullGrid`, then visit cell pairs `{i, 80 - i}` (180-degree symmetry, my call) in shuffled order and blank a pair only if the puzzle stays unique, and for Easy also `solvesWithSingles`. Easy and Medium stop once givens are at most `GIVENS[d] + 1`; Hard visits every pair (a minimal symmetric puzzle). Hard keeps the result only if `!solvesWithSingles`, else starts over from a new `fullGrid`, up to 20 tries, then keeps the last try. Easy and Medium also start over if the visit ends above the target.

### Task 2: Rules: setup, entries, pencil marks, own-move undo, leaving and the end

**Files:**
- Create: `games/sudoku/types.ts`, `games/sudoku/rules.ts`, `games/sudoku/index.ts`
- Test: `games/sudoku/rules.test.ts`, `games/sudoku/manager.test.ts`

**Interfaces:**
- Consumes: Task 1; chunk 0's `modeOf`, `playsAtOnce`, `RaceBoards`, `Contributions`, `addContribution`, `GameDefinition.continuesAlone`, `GameDefinition.undoOwn`, `manager.undoOwn(roomId, seat)`.
- Produces (`types.ts`):
  ```ts
  type Board = { entries: number[]; by: (Seat | null)[] }; // 81 each; entries 0 = empty; givens are never in entries
  type OwnMove = { cell: number; before: number; beforeBy: Seat | null; after: number }; // after 0 = an erase
  type LastMove =
    | { type: 'enter'; playerNumber: Seat; cell: number; digit: number; finished?: true }
    | { type: 'erase' | 'undoOwn'; playerNumber: Seat; cell: number };
  type GameState = BaseGameState & {
    difficulty: Difficulty; givens: number[]; solution: number[];
    board: Board;                              // Solo and Together
    raceBoards: RaceBoards<Board>;             // Race, one per seat
    notes: Partial<Record<Seat, number[]>>;    // 81 bitmasks per seat, bit d for digit d
    ownMoves: Partial<Record<Seat, OwnMove[]>>; // Together and Race
    showMistakes: boolean;                     // Solo
    raceWrong: Partial<Record<Seat, true>>;    // a full Race board that is wrong
    lastMove: LastMove | null;
  };
  ```
- Produces moves (Solo, through `applyMove`) and recorded actions (Together and Race, through `applyAction`), the same two shapes: `{ type: 'enter', cell: number, digit: number }` and `{ type: 'erase', cell: number }`. One function `place(state, seat, cell, digit | 0): Result<GameState>` serves both paths.
- Produces unrecorded actions in every mode: `{ type: 'note', cell: number, digit: number }` (toggles the seat's own mark) and `{ type: 'showMistakes', on: boolean }` (Solo only).
- Produces: `recordsAction(state, seat, action)` true only for `enter` and `erase` when `playsAtOnce(modeOf(state, MODE_RULE))`; `undoOwn(state, seat): Result<GameState>`; `onPlayerLeft`; `finalStandings(state): Standing[]`.

Decisions:
- `resetLobby(state, random)`: generate a new puzzle only when `givens` is empty or `difficulty` differs from the house rule; then rebuild empty `board`, one empty Race board per active seat when the mode is Race, and empty `notes`, `ownMoves`, `raceWrong`. `gameStatus`: Solo `Solve the puzzle`, Together `Everyone plays at once on one board`, Race `Race: everyone has the same puzzle; first to finish wins`.
- Every action (`enter`, `erase`, `note`, `showMistakes`) returns `started: true`, so it meets the platform's agreement gate, as a Hearts pass does.
- Refusals (exact copy): game over `The game is over`; bad cell `Pick a square`; bad digit `Pick a digit from 1 to 9`; a given `That square is a given`; Together writing or erasing a correct entry `That square is already correct`; Together erasing another seat's entry that is not wrong `You can only erase your own or wrong entries`; Solo entries sent as actions, or Together and Race entries sent as moves, `Wrong kind of entry for this mode`; `showMistakes` outside Solo `Mistakes are shown only in Solo`; `undoOwn` in Solo `Solo uses Undo`; nothing to take back `Nothing of yours to undo`.
- Entering a digit clears that seat's own notes on that cell. Together and Race push an `OwnMove` on the seat's stack.
- `undoOwn`: pop the seat's moves until one whose cell still holds its `after` with `by` this seat (moves a friend has since changed are dropped as stale); restore `before` and `beforeBy`; none left gives the error. In Race only the seat's own board is touched. Clears the seat's `raceWrong`.
- End: Solo and Together end when every cell equals `solution`: `isGameOver`, `currentPlayer: null`, `winners` every active seat, status `Solved!` (Solo) or `Solved together!`. Race: an entry that fills a seat's board ends the game with that seat as the only winner when correct (status `<name> finished first!`, `lastMove.finished: true`), else sets `raceWrong[seat]`; any entry, erase or undo on that board clears it.
- `onPlayerLeft(state, seat)`: Together keeps the leaver's entries; both modes drop the leaver's `notes`, `ownMoves` and `raceWrong`, and Race drops their board. Nobody wins by default (`continuesAlone`).
- `finalStandings`: Solo and Together: every active seat place 1, score `<n> squares` (entries by that seat, counted with `addContribution`; Solo shows `Solved`). Race: the winner place 1 with `Solved`, the rest by the share of non-given cells that are correct, highest first, equal shares sharing a place, score `<p>% correct`.
- `index.ts`: `sudoku: GameDefinition<GameState, PublicGameState>` with `info`, `createGameState`, `resetLobby`, `applyMove`, `applyAction`, `recordsAction`, `undoOwn`, `continuesAlone: true`, `onPlayerLeft`, `finalStandings`, and Task 3's view hooks (add them there).
