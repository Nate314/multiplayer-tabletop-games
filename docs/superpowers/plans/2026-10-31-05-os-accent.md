# Home Page Accent Follows the OS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The lobby's green accent (`--lobby-accent` and its hover and text tokens) becomes the operating system's accent color in browsers that support the CSS `AccentColor` system color, and stays green everywhere else.

**Architecture:** CSS only. One `@supports` block at the end of the token section of `src/App.scss` overrides the three `--lobby-accent*` custom properties in both themes. Every place that already reads those tokens (landing page, join dialog, stats page, and the platform defaults inside games through `var(--platform-button-bg, var(--lobby-accent))`) follows automatically. Text on the accent uses `AccentColorText`.

**Tech Stack:** SCSS (Vite, dart-sass), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-31-pause-resume-jenga-and-fixes-design.md`, section 5. Index plan: `docs/superpowers/plans/2026-10-31-pause-resume-jenga-and-fixes.md` (Shared contracts, ports, Global Constraints, Combining). Branch `os-accent` from `pause-resume-jenga-and-fixes`. Server PORT 3205, E2E_PORT_BASE 6490.

## Global Constraints

All of the index plan's Global Constraints, plus:

- Only the tokens `--lobby-accent`, `--lobby-accent-hover` and `--lobby-accent-text` change. Their existing values in `:root` and `:root[data-theme="dark"]` stay as the fallback, byte for byte.
- The feature check is `@supports (color: AccentColor) and (color: color-mix(in srgb, AccentColor 80%, black))`. The second condition keeps the hover color from falling back to green while the button turns blue in a browser that has `AccentColor` but no `color-mix` (Firefox 103 to 112).
- Values inside the block, exactly:
  - Light (`:root`): `--lobby-accent: AccentColor; --lobby-accent-hover: color-mix(in srgb, AccentColor 80%, black); --lobby-accent-text: AccentColorText;`
  - Dark (`:root[data-theme="dark"]`): `--lobby-accent: AccentColor; --lobby-accent-hover: color-mix(in srgb, AccentColor 85%, white); --lobby-accent-text: AccentColorText;`
  - These mirror today's hover direction: darker on hover in light mode (`#2d6a4f` to `#24563f`), lighter in dark mode (`#3f8f6b` to `#4ba67d`).
- The block sits directly after the `:root[data-theme="dark"]` block, so equal specificity and later source order make it win in both themes.
- Rulings (state them in the PR's Rulings):
  - The separate literal defaults that happen to share the green (`--dice-selected-default`, `--drag-over-default`, `--piece-tray-selected-default`) and the `theme-color` meta in `index.html` are not the accent token and stay as they are. The spec names "the same accent token", and these are piece highlights and the browser bar.
  - Games that set their own `--platform-button-*` (Go Fish and others) keep their own colors; only the lobby fallback follows the OS.
- No change to `src/components/ThemeToggle.tsx` or `index.html`.
- Browser fact found while planning: Playwright's Chromium 141 reports `CSS.supports('color', 'AccentColor')` false and resolves `AccentColor` to `rgb(0, 0, 0)` as an unknown value, so in Chrome the green stays, as the spec expects. The installed Playwright (1.56) wants Firefox build 1495, which is not installed (1482 and 1532 are).

## Review Focus

1. A light OS accent (yellow, pale cyan) on the Join button: the label must stay readable, which `AccentColorText` handles; a hard-coded `#ffffff` left anywhere on an accent background would fail (Task 1 grep step and Task 2 Firefox check).
2. Dark theme with a dark OS accent (navy): the accent used as foreground on the dark surface (`.lobby-game-icon`, `.stats-link-url`, disabled checkbox tick, `.lobby-game-house-rule` border) can lose contrast. Not text on an accent background, so the spec does not cover it; Task 2 checks it with a dark accent and reports it under Known gaps if it is poor.
3. The dark theme toggled while the page is open: the `@supports` block must override the dark values too, not only `:root` (Task 1 test asserts both rules).
4. Chrome and other unsupported browsers must render exactly today's green and white (Task 1 test asserts the computed colors in Chromium).
5. A game's own palette must not be overridden: a game that sets `--platform-button-bg` keeps it inside its `[data-game]` (Task 2 checks Go Fish).

- [ ] **Step 1: Write the failing tests in `e2e/landing.spec.ts`**

Two tests, using the file's existing `landing(browser, server)` helper. Open the join dialog with `card(page, 'Connect Four').click()`; the dialog's submit button has class `lobby-button-primary`.

```ts
test('the lobby accent follows the OS accent color where the browser supports AccentColor', async ({ browser, server }) => {
  const { page } = await landing(browser, server);
  // Finds the @supports rule in the loaded stylesheets and reads the tokens it sets per selector
  const rules = await page.evaluate(() => {
    const found: Record<string, Record<string, string>> = {};
    for (const sheet of Array.from(document.styleSheets)) {
      for (const rule of Array.from(sheet.cssRules)) {
        if (!(rule instanceof CSSSupportsRule) || !rule.conditionText.includes('AccentColor')) continue;
        for (const inner of Array.from(rule.cssRules)) {
          if (!(inner instanceof CSSStyleRule)) continue;
          found[inner.selectorText] = Object.fromEntries(['--lobby-accent', '--lobby-accent-hover', '--lobby-accent-text']
            .map(name => [name, inner.style.getPropertyValue(name).trim()]));
        }
      }
    }
    return found;
  });
  expect(rules[':root']).toEqual({
    '--lobby-accent': 'AccentColor',
    '--lobby-accent-hover': 'color-mix(in srgb, AccentColor 80%, black)',
    '--lobby-accent-text': 'AccentColorText'
  });
  expect(rules[':root[data-theme="dark"]']).toEqual({
    '--lobby-accent': 'AccentColor',
    '--lobby-accent-hover': 'color-mix(in srgb, AccentColor 85%, white)',
    '--lobby-accent-text': 'AccentColorText'
  });
});

test('browsers without AccentColor keep the green accent in both themes', async ({ browser, server }) => {
  const { page } = await landing(browser, server);
  expect(await page.evaluate(() => CSS.supports('color', 'AccentColor'))).toBe(false);
  await card(page, 'Connect Four').click();
  const join = page.locator('.lobby-button-primary');
  await expect(join).toHaveCSS('background-color', 'rgb(45, 106, 79)');
  await expect(join).toHaveCSS('color', 'rgb(255, 255, 255)');
  await page.evaluate(() => document.documentElement.setAttribute('data-theme', 'dark'));
  await expect(join).toHaveCSS('background-color', 'rgb(63, 143, 107)');
  await expect(join).toHaveCSS('color', 'rgb(255, 255, 255)');
});
```

If the browser serializes the custom property values differently (for example lowercased keywords or different spacing), match what Chromium returns for the exact source text in Global Constraints and note it in the PR; do not change the source values to suit the test.
